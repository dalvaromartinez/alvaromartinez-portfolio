01 · Project overview

Problem, context and objective.

FarmaStock AI explores how Generative AI can be applied to a realistic pharmacy stock scenario, where sales movements, purchases, manual corrections and inventory evolution need to be interpreted clearly.

The problem

Pharmacy stock information is often distributed across exports, operational movements and manual adjustments. Understanding what happened, why it happened and how it affects stock decisions can be time-consuming.

The approach

The project uses a Retrieval-Augmented Generation architecture to answer questions with project-specific context, avoiding generic responses and grounding the assistant in documented logic.

The outcome

A functional Streamlit demo that lets users ask questions about the project, the stock logic, the analytical pipeline and the technical decisions behind the solution.

02 · Technical architecture

RAG pipeline with agentic orchestration.

The assistant is structured as a modular workflow where retrieval, reasoning and answer generation are separated to make the system easier to understand, test and extend.

Technical stack

The project combines data, AI and product-oriented tools.

Python Streamlit LangGraph Gemini ChromaDB RAG Pandas Markdown GitHub

Repository structure

The repo is organized to separate application code, documentation, notebooks and reusable logic.

User question

The user asks a question through the Streamlit interface about stock, process, architecture or project logic.

Workflow orchestration

LangGraph defines the route of the interaction and separates the main stages of the assistant.

Context retrieval

ChromaDB retrieves the most relevant project context to ground the response.

Answer generation

Gemini generates a final answer using the retrieved context and the system instructions defined for the assistant.

03 · Results and learning

What the project demonstrates.

Instead of presenting only a notebook, the project is packaged as a professional AI product prototype with a usable interface, documented decisions and a clear publication strategy.

Main results

  • Functional RAG assistant for a specific pharmacy stock domain.
  • Streamlit interface to demonstrate the project interactively.
  • LangGraph-based workflow to make the assistant easier to explain.
  • Vector retrieval layer with ChromaDB.
  • Professional GitHub publication with README and project structure.

Critical reflection

  • The next step would be connecting the assistant to real pharmacy exports.
  • Evaluation could be improved with a structured test set of domain questions.
  • Traceability could be expanded by showing retrieved chunks in the UI.
  • The analytical layer could evolve into forecasting and reorder recommendations.
